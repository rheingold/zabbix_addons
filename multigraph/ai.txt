PROJECT OVERVIEW
================================================================================

PROJECT: Multigraph Widget for Zabbix 7.4.3+
VERSION: 0.1.1 (Development - Untested for Classic UI)
STARTED: November 5, 2025
LAST UPDATED: November 10, 2025

TEAM:
  Lead & Architecture: lukas@plachy.eu
  Development: Claude Sonnet 4 (AI Assistant, Anthropic)

DESCRIPTION:
  Custom Zabbix dashboard widget for pattern-based multi-item graph visualization.
  Instead of manual item selection, uses wildcard/regex patterns to dynamically
  match items by name, enabling flexible multi-metric graphs.

REPOSITORY: https://github.com/rheingold/zabbix_addons
BRANCH: tmp0.1 (development)
LICENSE: MIT

TECHNOLOGY STACK:
  Backend: PHP 8.4+ (Zabbix 7.x requirement)
  Frontend: JavaScript ES6+, HTML5 Canvas
  Framework: Zabbix Widget Framework (MVC)
  API: Zabbix API (Item, History)
  Deployment: Docker (optional), SSH, PowerShell scripts

================================================================================
MAIN OBJECTIVES (D.2.1)
================================================================================

1. PATTERN-BASED ITEM SELECTION
   Enable users to match items using wildcards (*, ?) or regular expressions
   instead of manual selection, allowing dynamic graphs that auto-include new items.

2. MULTI-ITEM VISUALIZATION
   Display multiple matched items in single graph with customizable colors,
   legend, and styling.

3. DASHBOARD INTEGRATION
   Full integration with Zabbix dashboard timeframe selector, supporting
   absolute, relative, and period-rounding timeframes.

4. CLIENT-SIDE RENDERING
   Fast HTML5 Canvas-based rendering with hover tooltips and responsive resize.

5. ZERO ZABBIX MODIFICATIONS
   Self-contained widget requiring no modifications to Zabbix core files.

================================================================================
FUNCTIONAL REQUIREMENTS (D.2.2)
================================================================================

D.2.2.1: Pattern Matching
  - Wildcard mode: *, ? characters for simple patterns
  - Regex mode: Full PCRE regex support
  - Case-sensitive matching
  - Max 100 items matched per query (configurable)

D.2.2.2: Multi-Host Support
  - Select multiple hosts
  - Match items across all selected hosts

D.2.2.3: Graph Rendering
  - HTML5 Canvas dual-layer architecture (base + overlay)
  - Time series line and area charts
  - Automatic Y-axis scaling or fixed range
  - Grid with configurable density
  - Legend with configurable position (top-left, right, bottom)

D.2.2.4: Interactivity
  - Hover tooltips showing value, timestamp, series name
  - Data point interpolation for smooth hover
  - Responsive resize with automatic redraw

D.2.2.5: Customization
  - Configurable colors (comma-separated hex)
  - Fill opacity (0-1)
  - Y-axis range (auto or fixed min/max)
  - Grid enable/disable
  - Text colors (legend, axes)

D.2.2.6: Timeframe Support
  - Absolute: Unix timestamp, ISO date strings
  - Relative: now-Xh, now-Xd, now-Xw, now-XM, now-Xy
  - Period rounding: now/d (today), now/w (week), now/M (month), now/y (year)
  - Integration with dashboard time selector

================================================================================
ARCHITECTURAL CONSTRAINTS (D.2.4)
================================================================================

1. WIDGET FRAMEWORK COMPLIANCE
   - Must extend Zabbix CWidget base class
   - MVC pattern: actions/ (controllers), includes/ (models), views/ (templates)
   - Namespace: Widgets\Multigraph\{Actions|Includes}
   - PSR-4 autoloading (directory names must match namespace)

2. DATA ACCESS
   - Use Zabbix API only (no direct database access)
   - API::Item()::get() for item matching
   - API::History()::get() for time series data

3. RENDERING ARCHITECTURE
   - Server-side: PHP controllers prepare data
   - Client-side: JavaScript renders to Canvas
   - No server-side image generation
   - No external JavaScript libraries (jQuery available from Zabbix)

4. DEPLOYMENT ISOLATION
   - Self-contained in /usr/share/zabbix/widgets/multigraph/
   - No modifications to Zabbix core files
   - manifest.json for registration
   - Scan directory for detection

CRITICAL LESSONS LEARNED (D.1 - Kept for AI Reference)
================================================================================

These are SOLVED issues - solutions documented in code comments and README.md.
Kept here ONLY for AI context to avoid repeating mistakes.

1. WIDGET DEVELOPMENT WORKFLOW
   LESSON: Configuration fields, data flow, view templates, JavaScript rendering
           must ALL align precisely or widget fails silently.
   SOLUTION: Documented in README.md Section B.10 (Source Structure)
   CODE: See PHPDoc headers in all source files

2. DATA STRUCTURE SYNCHRONIZATION
   LESSON: PHP array structure from WidgetView MUST exactly match JavaScript
           expectations in class.widget.js. Mismatches cause blank widgets.
   SOLUTION: Documented in class.widget.js::setContents() JSDoc
   CODE: WidgetView.php prepareGraphData() + class.widget.js structure comments

3. TIMEFRAME PARSING
   LESSON: Zabbix dashboard time selector uses expressions like "now/w", "now/M"
           that require special parsing logic for period rounding.
   SOLUTION: Implemented parseZabbixTime() method in WidgetView.php
   CODE: WidgetView.php lines 50-150 (parseZabbixTime method with full docs)

4. CANVAS RENDERING ORDER
   LESSON: Draw order matters: grid → fills → lines → legend. Wrong order causes
           fills to obscure lines or legend to be unreadable.
   SOLUTION: Documented in class.widget.js::renderGraph() phases
   CODE: class.widget.js lines 200-600 (13-phase rendering pipeline)

5. EVENT LISTENER CLEANUP
   LESSON: Overlay canvas event listeners accumulate on redraw, causing multiple
           tooltips. Must clone element to remove old listeners.
   SOLUTION: Documented in class.widget.js hover setup
   CODE: class.widget.js line ~550 (overlay clone logic)

6. ZABBIX FRAMEWORK CONSTRAINTS
   LESSON: Zabbix 7.4.3 has NO setHelpHint() method on form fields (unlike docs).
           Using it causes fatal errors. Must use Zabbix API only, no DB access.
   SOLUTION: Removed setHelpHint() calls, added inline comments instead
   CODE: WidgetForm.php (no setHelpHint calls, comments explain fields)

DEBUGGING TIPS
================================================================================

PHP ERRORS:
  - Check: /var/log/apache2/error.log or /var/log/nginx/error.log
  - Check: /var/log/php8.4-fpm.log
  - Enable debug: $DB['DB_DEBUG'] = 1 in /etc/zabbix/web/zabbix.conf.php

JAVASCRIPT ERRORS:
  - Browser console: F12 → Console tab
  - Check for: "graph_data is undefined", "querySelector returned null"
  - Verify container exists: document.querySelector('.multigraph-container')
  - Verify data structure: console.log(response.graph_data)

DEPLOYMENT ISSUES:
  - Verify files copied: ls -la /usr/share/zabbix/widgets/multigraph/
  - Check permissions: chmod -R 755, chown -R www-data:www-data
  - Verify manifest: cat manifest.json | python -m json.tool
  - Clear browser cache: Ctrl+Shift+Delete

PATTERN MATCHING ISSUES:
  - Test pattern manually: Configuration → Hosts → Items → Browser search (Ctrl+F)
  - Check case sensitivity
  - Verify regex syntax: regex101.com
  - Check Zabbix API logs for errors

PERFORMANCE ISSUES:
  - Reduce timeframe (shorter = fewer data points)
  - Reduce matched items (more specific pattern)
  - Check browser performance: F12 → Performance tab
