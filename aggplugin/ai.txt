*** PROJECT OVERVIEW ***
Zabbix Agent2 external plugin for Windows providing continuous metric aggregation with comprehensive statistics (avg, min, max, median, mode, standard deviation, variance).

🎉 NEW: PLUGIN FRAMEWORK - Extensible architecture supporting loadable measurement plugins (DLL files)

ARCHITECTURE:
- Agent2 external plugin: Go wrapper + C++ aggregation engine + Plugin framework
- Communication: Named pipes (Windows IPC between Agent2 and plugin process)
- Core engine: cpp_common/collector.cpp (background sampling thread, 1-second interval)
- Platform layer: cpp_common/plugin_common.cpp (Windows API samplers for built-in metrics)
- Plugin system: cpp_common/plugin_loader.cpp (dynamic DLL loading, plugin lifecycle)
- Plugin API: cpp_common/measurement_plugin_api.h (C interface for plugins)
- Go wrapper: go_agent2_wrapper/main.go (CGO bindings + Zabbix SDK)
- Build system: build_cpp.ps1 (main build), build_example_plugin.ps1 (plugin build)

PLUGIN FRAMEWORK COMPONENTS:
- measurement_plugin_api.h: C interface specification (required/optional functions, data types)
- plugin_loader.cpp: Dynamic loading (discovery, validation, lifecycle management)
- collector_plugin_integration.cpp: Bridge layer (connects plugins to collector)
- example_plugins/disk_stats_plugin.c: Complete example plugin (PDH-based disk I/O)
- PLUGIN_DEVELOPMENT.md: Comprehensive developer guide (721 lines)
- PLUGIN_ARCHITECTURE.md: Architecture documentation (598 lines)
- PLUGIN_QUICKREF.md: Quick reference card (188 lines)

PLUGIN FEATURES:
- Dynamic discovery: Wildcard-based plugin scanning (e.g., plugins/*.dll)
- Multi-source metrics: Support per-CPU, per-disk, per-interface metrics
- Configuration: Per-plugin [plugin.name] sections in aggplugin.conf
- Thread-safe: Plugin collection runs in background thread
- Memory managed: Plugin allocates, framework frees
- Error handling: COLLECT_OK, COLLECT_ERROR, COLLECT_NOTSUPPORTED, COLLECT_TIMEOUT

KEY TECHNICAL DETAILS:
- Sampling: Background thread samples metrics every 1 second
- Storage: All samples stored in memory (vector) for statistics computation
- Thread safety: Mutex-protected accumulator (lock only during add/fetch)
- Reset pattern: Each query (fetch) returns JSON and resets accumulator
- Statistics: Computed on-demand during fetch (median via sort, mode via frequency map)
- Memory: ~8 bytes per sample × MaxSamples (default 1000) per metric
- Auto-reset: When MaxSamples reached, accumulator clears automatically

STATISTICS COMPUTED:
- avg: arithmetic mean
- min: minimum value
- max: maximum value  
- med: median (50th percentile)
- mod: mode (most frequent rounded value)
- dev: standard deviation
- var: variance
- cnt: sample count

*** PLUGIN FRAMEWORK (Added November 14, 2025) ***

OVERVIEW:
The aggplugin framework now supports loadable measurement plugins - lightweight DLLs that extend
the system with custom metrics without modifying core code.

ARCHITECTURE:
┌─────────────────────────────────────────────────────────────┐
│  Go Wrapper → Collector Core → Plugin Integration Layer    │
│                                      ↓                       │
│                         Plugin Loader (plugin_loader.cpp)   │
│                                      ↓                       │
│              ┌───────────────────────┴───────────────────┐  │
│              ↓                       ↓                   ↓  │
│     disk_stats.dll          network_stats.dll    custom.dll│
│  (Measurement Plugins - User-provided)                     │
└─────────────────────────────────────────────────────────────┘

PLUGIN API (measurement_plugin_api.h):
Required Functions (must be exported by DLL):
- plugin_get_info() → Returns plugin metadata, registers keys
- plugin_init(config) → Initialize with configuration
- plugin_collect(results) → Collect measurements (called every interval)
- plugin_deinit() → Clean up resources

Optional Functions:
- plugin_on_reset(key) → Notification when data consumed
- plugin_aggregate_custom(...) → Custom aggregation logic
- plugin_on_init_complete() → Post-initialization callback

Data Types:
- metric_value_type_t: FLOAT, UINT64, STRING, TEXT, LOG
- collect_status_t: OK, ERROR, NOTSUPPORTED, TIMEOUT
- measurement_value_t: {source_id, value, str_value}
- collection_result_t: {key, status, value_count, values[]}

PLUGIN LIFECYCLE:
1. Discovery: Scan PluginPath pattern (e.g., C:\Zabbix\plugins\*.dll)
2. Loading: LoadLibrary() → GetProcAddress() → Validate functions → plugin_init()
3. Sampling: Continuous loop calls plugin_collect() for each plugin
4. Querying: Fetch aggregated stats → plugin_on_reset() callback
5. Shutdown: plugin_deinit() → FreeLibrary()

MULTI-SOURCE METRICS:
Plugin can return multiple values per key (one per source):
- Example: disk.io.read returns 3 values: {"sda": 123.4, "sdb": 567.8, "sdc": 890.1}
- Zabbix item: aggplugin.disk.io.read[sda,avg,60]
- Cache storage: disk.io.read.sda, disk.io.read.sdb, disk.io.read.sdc

MEMORY MANAGEMENT:
- Plugin allocates: values array, source_id strings, str_value strings
- Framework frees: All plugin-allocated memory after processing
- Pattern: malloc/strdup in plugin, free() in framework

CONFIGURATION:
aggplugin.conf format:
[Plugins]
PluginPath=C:\Zabbix\plugins\measurements\*.dll

[plugin.disk_stats]
enabled=1
devices=0,1,2

[plugin.network_stats]
enabled=1
interfaces=Ethernet,WiFi

DESIGN PRINCIPLES:
- Simple C interface (no C++ complexity for plugin authors)
- Compatible with Zabbix agent datatypes and conventions
- Support dynamic sources (devices appearing/disappearing)
- Minimal boilerplate (~100 lines typical)
- Thread-safe (plugin_collect from sampling thread, plugin_on_reset from query thread)
- Fast collection (< 100ms target for plugin_collect)

THREAD SAFETY:
- plugin_collect(): Called from background sampling thread
- plugin_on_reset(): Called from query/response thread
- Plugins must use mutexes if sharing state between functions

ERROR HANDLING:
- COLLECT_ERROR: Temporary failure, retry next interval
- COLLECT_NOTSUPPORTED: Permanent failure, metric not available
- COLLECT_TIMEOUT: Collection timeout
- Logging: fprintf(stderr, ...) captured by aggplugin in debug mode

PERFORMANCE CONSIDERATIONS:
- Target: < 100ms per plugin_collect() call
- Memory: ~8 bytes per sample × MaxSamples per metric
- Multi-source: 10 disks × 2 metrics = 20 accumulators = 160 KB (acceptable)
