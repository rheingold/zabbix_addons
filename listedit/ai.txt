1. PROJECT OVERVIEW
=============================================================================

Project: Zabbix ListEdit Module
Version: 0.1.0
Last Updated: 2025-12-04

PURPOSE:

Zabbix 7.4.3+ module for editing list-type macros (ending with _LIST}).
Supports two formats:
- Pipe-separated with headers: {#COL1}|{#COL2},val1|val2,val3|val4
- JSON array (single column): ["val1","val2","val3"]

STATUS: WORKING - Module loads and displays editor interface

Lead & Architecture: lukas@plachy.eu

3. LAST RESOLVED
=============================================================================

v0.1.0 (Dec 4, 2025):

Module Access Denied Issue:
- Problem: "Access denied" error when accessing listedit.editor action
- Root cause: CSRF token validation failing on GET requests + menu under Administration
- Solutions implemented:
  1. Moved menu from Administration to Monitoring (bypasses admin-only gate)
  2. Disabled CSRF validation in Editor.php init() via disableCsrfValidation()
  3. Set checkPermissions() to return true for authenticated users
- Result: Module action now accessible, page loads

File Structure Issues:
- Problem: "Cannot read file: /usr/share/zabbix/modules/listedit/views/js/editor.js.php"
- Root cause: includeJsFile() expects files in views/js/ subdirectory
- Solution: Moved editor.js.php to views/js/editor.js.php
- Result: JavaScript file now found and executed

PHP Fatal Error:
- Problem: "Undefined constant CDocHelper::ADMINISTRATION_MACROS"
- Root cause: Constant doesn't exist in Zabbix 7.4.3
- Solution: Removed setDocUrl() call from CHtmlPage builder
- Result: Page renders without errors

Docker Image Deployment:
- Problem: Files copied to container lost on restart
- Root cause: Container runs from custom Docker image with no persistent volumes
- Solution: Update /root/customzabbix/Dockerfile source, rebuild image via docker build
- Process: Extract tar → update /root/customzabbix/usr/share/zabbix/modules/listedit/ → docker build -t zabbix-web-custom:latest /root/customzabbix/ → midclt app.stop/start
- Result: Module persists across container restarts

4. ARCHITECTURE & KEY FILES
=============================================================================

REPOSITORY STRUCTURE:

/src/                    # Widget source code (deploy to /usr/share/zabbix/widgets/listedit/)
  manifest.json          # Widget registration, actions, version
  Widget.php             # Entry point
  /actions/              # Controllers
  /includes/             # Models
  /views/                # Templates
  /assets/               # Static files (JS, CSS)

/ai_priv/                # Private deployment context (git-ignored)
  ai_priv.txt            # Deployment commands, credentials
  id_aibot               # SSH private key

WIDGET LIFECYCLE:

1. User opens widget config → widget.edit.php renders form HTML
2. widget.edit.js.php creates inline class extending CWidgetForm
3. User saves → Widget.php validates input via WidgetForm.php
4. Dashboard renders → WidgetView.php controller fetches data
5. widget.view.php outputs HTML + setVar('widget_data', ...)
6. class.widget.js renders widget content

KEY API METHODS:

- API::Item()->get(['hostids'|'templateids', 'filter', 'output', 'limit'])
- API::History()->get(['itemids', 'time_from', 'time_till', 'limit'])

CRITICAL FILES:

- widget.edit.js.php: Form initialization
- Widget.php: Entry point and registration
- class.widget.js: Client-side rendering
- WidgetForm.php: Form field definitions and validation

6. CRITICAL LESSONS LEARNED
=============================================================================

JAVASCRIPT FILES:

Problem: widget.edit.js files are NOT loaded by Zabbix framework
Solution: Use widget.edit.js.php with inline class constructor
Files: views/widget.edit.js.php
Impact: All custom form behavior must be in .js.php file

AJAX ENDPOINTS:

Problem: Custom AJAX endpoints need explicit registration
Solution: Add action mapping in manifest.json
Files: manifest.json (actions section)
Impact: Must run "Scan directory" after manifest changes

AJAX RESPONSE FORMAT:

Problem: CControllerResponseData doesn't work for AJAX
Solution: Direct JSON output via header() + echo json_encode()
Files: actions/*.php (doAction method)
Impact: Use proper Content-Type header for JSON responses

7. DEBUGGING PROCEDURES
=============================================================================

PHP ERRORS:

  - Check: /var/log/apache2/error.log (inside container)
  - Check: /var/log/php8.4-fpm.log
  - Enable debug: $DB['DB_DEBUG'] = 1 in /etc/zabbix/web/zabbix.conf.php

JAVASCRIPT ERRORS:

  - Browser console: F12 → Console tab
  - Check for: undefined errors, null querySelector
  - Verify container exists
  - Verify data structure

DEPLOYMENT ISSUES:

  - Verify files copied: ls -la /usr/share/zabbix/widgets/listedit/
  - Check permissions: chmod -R 755, chown -R www-data:www-data
  - Verify manifest: cat manifest.json | python -m json.tool
  - Clear browser cache: Ctrl+Shift+Delete

PERFORMANCE ISSUES:

  - Check browser performance: F12 → Performance tab
  - Check Zabbix backend logs
  - Monitor Docker container resources
