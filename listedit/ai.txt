1. PROJECT OVERVIEW
=============================================================================

Project: Zabbix ListEdit Module
Version: 0.2.0
Last Updated: 2025-12-15

PURPOSE:

Zabbix 7.4.3+ module for editing list-type macros (ending with _LIST}).
Supports two formats:
- Pipe-separated with headers: {#COL1}|{#COL2},val1|val2,val3|val4
- JSON array (single column): ["val1","val2","val3"]

New in v0.2.0:
- Template macro inheritance (BFS traversal of nested templates)
- Host macros + template macros merged in selector
- Origin labels (host vs template: name) in dropdown
- Escaped JSON parsing for array values
- Theme-aware backgrounds and Zabbix-compliant styling
- Improved UI with proper height alignment and working Cancel button

STATUS: PRODUCTION READY - Module fully functional with enhanced features

3. LAST RESOLVED
=============================================================================

v0.2.0 ENHANCEMENTS (Dec 15, 2025):

✅ SOLVED: Macro Dropdown Text Display (Dec 15)
- Problem: Selected macro text not showing in dropdown after selection
- Root cause: Type mismatch between option values (numbers) and selected value (strings)
- Solution: Convert all option values to strings using String(macro.hostmacroid) for consistency
- Result: Dropdown now displays selected macro name correctly with origin label

✅ SOLVED: UI Height Alignment Issues (Dec 15)
- Problem: Host/template display too tall, dropdown text cut off with excessive padding
- Root cause: Inconsistent padding and height values between elements
- Solution: Set both to height: 32px with padding: 6px, then reduced display to 22px/3px padding
- Result: Proper visual alignment with all text fully visible

✅ SOLVED: Cancel Button Not Working (Dec 15)
- Problem: Cancel button in host search dialog didn't close the dialog
- Root cause: Duplicate ID "close-host-search" on both close (✕) button and Cancel button
- Solution: Renamed Cancel button to "host-search-cancel" with separate click handler
- Result: Both close (✕) and Cancel buttons now properly close the dialog

✅ SOLVED: Template Macro Inheritance (Dec 14)
- Problem: Only showing direct host macros, not inherited template macros
- Root cause: API::Host()->get(['selectParentTemplates']) only returns first-level parents
- Solution: Implemented BFS traversal to recursively fetch nested template inheritance chain
- Result: All inherited macros from nested templates now visible in selector

✅ SOLVED: Macro Origin Labeling (Dec 14)
- Problem: Users couldn't distinguish between host macros and template macros
- Root cause: No origin information attached to macro records
- Solution: Added 'origin' and 'origin_name' fields to each macro in MacroList.php
- Result: Dropdown shows "(host)" or "(template: TemplateName)" for each macro

✅ SOLVED: Escaped JSON Parsing (Dec 14)
- Problem: JSON array values like ["C:\", "D:\"] showing as escaped strings [\"C:\", \"D:\"]
- Root cause: Zabbix stores values in description field with escaped quotes
- Solution: Added unescapeZabbixJson() helper to convert \" back to "
- Result: JSON arrays parse correctly and render as editable tables

✅ SOLVED: Stale Cache After Save (Dec 14)
- Problem: Macro changes visible only after page reload
- Root cause: state.allMacros not updated after successful save
- Solution: Update state.allMacros in save callback with fresh data
- Result: Changes reflect immediately in UI without reload

✅ SOLVED: Theme Background Transparency (Dec 14)
- Problem: Dialog and panels had transparent backgrounds, hard to read
- Root cause: No background styling, inherited default transparency
- Solution: Applied Zabbix CSS classes - dialogue-body (dark) for dialog, ui-widget-content (light) for panels
- Result: Proper theme-aware backgrounds matching Zabbix UI

✅ SOLVED: Button Styling Mismatch (Dec 14)
- Problem: Buttons had custom blue colors not matching Zabbix defaults
- Root cause: Custom CSS with accent colors and shadows
- Solution: Changed to Zabbix standard - transparent background, gray text (#768d99), gray borders (#acb5c2)
- Result: Buttons now match Zabbix default UI style

v0.1.0 FULL CYCLE (Dec 2-7, 2025):

✅ SOLVED: Module Initialization & Action Routing (Dec 5)
- Problem: Module not recognized by Zabbix, returning "Page not found" for all actions
- Root cause: Missing getActions() method in Module.php; manifest.json alone doesn't register actions
- Solution: Added getActions() returning action map with class names (Editor, HostList, MacroList, MacroUpdate)
- Result: Actions now properly routed to controller classes

✅ SOLVED: JavaScript "MacroListEditor is not defined" (Dec 5)
- Problem: Inline init code in editor.js.php ran before listedit.js loaded (race condition)
- Root cause: Zabbix's addJsFile() loads JS asynchronously via jsLoader.php
- Solution: Inlined entire MacroListEditor IIFE directly into editor.js.php with synchronous init
- Result: MacroListEditor defined and functional on page load

✅ SOLVED: Form Rendering as Plain Text (Dec 7)
- Problem: HTML form elements showing as escaped text instead of rendered markup
- Root cause: Zabbix CSelect/CHtmlPage classes escaping HTML; CRaw class doesn't exist
- Solution: Switched to raw HTML `<select>` element and direct PHP view output (no CHtmlPage wrapper)
- Result: Dropdown and form now render properly

✅ SOLVED: Class Name Resolution Error (Dec 5)
- Problem: "Class Modules\ListEdit\Actions\Modules\ListEdit\Actions\Editor not found"
- Root cause: getActions() returning fully qualified names; Zabbix auto-prefixes with module namespace
- Solution: Return short class names (Editor, HostList, etc) instead of full namespaces
- Result: Correct class resolution and action dispatch

✅ SOLVED: Syntax Errors in Module.php (Dec 5)
- Problem: "Unexpected token public" in Module.php on deployment
- Root cause: Long lines breaking during tar/deployment causing malformed PHP
- Solution: Refactored class_alias to multi-line if statement
- Result: Valid PHP syntax on deployed files

4. ARCHITECTURE & KEY FILES
=============================================================================

REPOSITORY STRUCTURE:

/src/                    # Module source code (deploy to /usr/share/zabbix/modules/listedit/)
  manifest.json          # Module registration, action definitions, version
  Module.php             # Entry point, getActions(), menu registration
  /actions/              # Controllers for each action
    - Editor.php         # Main page (renders editor.php view)
    - HostList.php       # AJAX endpoint for hosts/templates list
    - MacroList.php      # AJAX endpoint for _LIST} macros
    - MacroUpdate.php    # AJAX endpoint for saving macro updates
  /views/                # View templates
    - editor.php         # Main form HTML, includes inline JS
    - editor.js.php      # Inline MacroListEditor JavaScript
  /assets/               # Static files
    - js/listedit.js     # DEPRECATED (now inlined in editor.js.php)
    - css/listedit.css   # Styling

MODULE LIFECYCLE:

1. Module registered via manifest.json + getActions() in Module.php
2. Menu entry created in init() (appears under Monitoring → Macro List Editor)
3. User clicks menu → routes to listedit.editor action
4. Editor.php action renders views/editor.php with inline JavaScript
5. JavaScript calls AJAX endpoints: listedit.hostlist, listedit.macrolist, listedit.macroupdate
6. Backend validates permissions and returns JSON responses

CRITICAL IMPLEMENTATION DETAILS:

- All JavaScript MUST be inline in editor.js.php (not in separate .js file) to avoid async loading race condition
- View file editor.php outputs raw PHP/HTML (not using CHtmlPage/CForm wrappers) for proper HTML rendering
- CSRF validation disabled in Editor action (required for menu access)
- Action responses use manual header() + json_encode() for JSON output
- Host list fetched via API::Template()->get() and API::Host()->get()
- Macros fetched via API::HostMacro()->get() and API::TemplateMacro()->get()

6. CRITICAL LESSONS LEARNED
=============================================================================

JAVASCRIPT LOADING:

Problem: Zabbix's addJsFile() loads scripts asynchronously via jsLoader.php, causing race conditions
Solution: Inline ALL JavaScript directly in view templates (editor.js.php) with no external file loading
Impact: Init code must wait for DOM or use setTimeout checks (prefer inlining entire module)

HTML RENDERING:

Problem: Zabbix CHtmlPage and form classes escape/transform HTML unexpectedly
Solution: Use raw PHP view output with manual HTML markup (no Zabbix wrapper classes)
Impact: Views must output plain HTML; CHtmlPage should only be used for admin/dashboard widgets

MODULE ACTION ROUTING:

Problem: Zabbix expects getActions() to return specific array format with class namespace rules
Solution: Return short class names only; Zabbix auto-prepends module namespace
Format: ['action.name' => ['class' => 'ClassName', 'view' => 'viewname', 'layout' => 'layout.json']]

AJAX ENDPOINTS:

Problem: Custom AJAX endpoints need explicit registration
Solution: Add action mapping in manifest.json
Files: manifest.json (actions section)
Impact: Must run "Scan directory" after manifest changes

AJAX RESPONSE FORMAT:

Problem: CControllerResponseData doesn't work for AJAX
Solution: Direct JSON output via header() + echo json_encode()
Files: actions/*.php (doAction method)
Impact: Use proper Content-Type header for JSON responses
