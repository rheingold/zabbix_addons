FUNCTIONAL REQUIREMENTS:
========================
New "Graph" & "Graph prototype" components that:
- Reference Items/Item prototypes by name via wildcard/regex (optional: derive regex parts from Zabbix macro lists)
- Display multiple matching items in single graph
- Visual compatibility with standard Zabbix graphs

ARCHITECTURE:
=============
1. SELF-REGISTRATION: Plugin auto-registers, zero modifications to existing Zabbix files
   - If patches unavoidable: use diff patch file + command (apply in Dockerfile)

2. RENDERING MODES (config via hidden advanced UI section):
   A) Server-side (PRIORITY): graphimagerenderer.php returns rendered image
   B) Client-side (LATER): JS library + same PHP returns JSON data
   
3. CLIENT RENDERING (Mode B): Dynamic refresh on timeframe change without full redraw (fetch data only)

⚠️⚠️⚠️ CRITICAL: WIDGET DEVELOPMENT WORKFLOW ⚠️⚠️⚠️
=======================================================
When adding/modifying widget configuration fields and rendering:

1. CONFIGURATION FIELDS (WidgetForm.php):
   - Define fields in WidgetForm.php->addFields()
   - Use integer constants for RadioButtonList (NOT strings!)
     Example: COLOR_MODE_CYCLE = 0, COLOR_MODE_RANDOM = 1
   - Set default values via ->setDefault()
   - Zabbix 7.4.3: NO setHelpHint() method exists!

2. DATA FLOW (GraphRenderer.php):
   - prepareGraphData() returns array structure
   - MUST match JavaScript expectations exactly!
   - Current structure: 
     {
       'series': [ {name, data: [[timestamp_ms, value], ...], color, units} ],
       'legend_position': int (0/1/2),
       'fill_opacity': float (0-1),
       'y_axis_label': string,
       'y_min': string ('auto' or number),
       'y_max': string ('auto' or number),
       'show_grid': bool,
       'grid_density': string ('auto' or number)
     }

3. VIEW TEMPLATE (widget.view.php):
   - Use CWidgetView + setVar() to pass data to JS
   - Create container with proper structure:
     <div class="multigraph-container">
       <canvas id="xxx_canvas"> (main graph)
       <canvas id="xxx_overlay"> (hover effects)
     </div>
   - Call: (new CWidgetView($data))->addItem($body)->setVar('graph_data', $data['graph_data'])->show()
   - DO NOT use inline JavaScript with CScriptTag!

4. JAVASCRIPT (assets/js/class.widget.js):
   - Extend CWidget class
   - Implement setContents(response) to receive data
   - Access data via response.graph_data (matches setVar key)
   - DO NOT render in onActivate() - data not ready yet!
   - Use this._target.querySelector() to find container
   - Data structure MUST match PHP output exactly
   - Draw order: grid → fills → lines → legend (so layers stack correctly)
   - For hover: Clone overlay to remove old event listeners
   - Text colors: Use '#000' for visibility (black text on light backgrounds)

5. DEPLOYMENT:
   - Deploy ALL files: views/, assets/js/, includes/
   - Rebuild Docker image after copying files
   - Restart container to load new code
   - Clear browser cache or add ?cachebuster to test

6. DEBUGGING:
   - Check browser console for JS errors
   - Verify container exists: querySelector('.multigraph-container')
   - Verify data structure: console.log(response.graph_data)
   - Check canvas size: canvas.width/height should be > 0
   - Grid not visible? Check fill opacity and draw order

COMMON PITFALLS:
- Using strings instead of integers for RadioButtonList
- Mismatched data structure between PHP and JS
- Rendering before data arrives (onActivate too early)
- Wrong querySelector (looking for wrong class/id)
- Fill opacity covering everything (draw fills before lines)
- Event listeners not cleaning up (clone element to reset)
