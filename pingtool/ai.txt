*** PROJECT OVERVIEW ***

**ARCHITECTURE CHANGE (December 2, 2025):**
Converted from standalone CLI tool to Zabbix Agent 2 Go plugin with CGO integration.

Zabbix Agent 2 external plugin for Windows providing on-demand ICMP ping functionality.
- On-demand execution (no background collector - unlike aggplugin)
- Single-target ping per call (parameters: target, count, timeout)
- JSON array output matching Zabbix conventions (proc.get, vfs.fs.get style)
- No admin privileges needed (uses Windows ICMP API)
- IPv4 and IPv6 support

=== ARCHITECTURE ===

**Components:**
1. Go Wrapper (main.go):
   - Implements Zabbix SDK plugin interface (plugin.Exporter)
   - Registers metric: ping.icmp[target,count,timeout]
   - Marshals parameters and calls C library via CGO
   
2. C Library (pingtool_lib.c):
   - Exports ping_execute() function for CGO
   - Performs IPv4/IPv6 ICMP ping operations
   - Builds JSON array string in buffer
   - Uses Windows ICMP API (IcmpSendEcho, Icmp6SendEcho2)

3. Windows ICMP API:
   - IcmpCreateFile() / Icmp6CreateFile()
   - IcmpSendEcho() / Icmp6SendEcho2()
   - No admin privileges required

**Data Flow:**
Zabbix Agent2 → Named Pipes → Go Plugin → CGO → C ping_execute() → Windows ICMP API → JSON result

**Key Difference from aggplugin:**
- NO background sampling thread
- NO continuous data collection
- Each metric call executes ping synchronously (blocking)
- Execution time: 1-10+ seconds (count × timeout)
- Suitable for on-demand checks, not high-frequency monitoring

=== OUTPUT FORMAT ===

**Default: Zabbix Array Format**
```json
[
  {"target":"192.168.254.1","seq":1,"ms":1.000,"ok":true},
  {"target":"192.168.254.1","seq":2,"ms":0.000,"ok":true},
  {"target":"192.168.254.1","seq":3,"ms":15.000,"ok":true},
  {"target":"192.168.254.1","type":"summary","success_ratio":1.0000,"avg_ms":5.333}
]
```

Format details:
- Flat JSON array (matches aggplugin convention)
- Each ping = one array element with target, seq, ms, ok fields
- Summary = final array element with type:"summary", success_ratio (0..1), avg_ms
- JSONPath: `$[?(@.type=="summary")].success_ratio` for success ratio
- JSONPath: `$[?(@.type=="summary")].avg_ms` for average response time

**LLD Mode (-output lld):**
Same structure but with discovery macros:
```json
[
  {"{#TARGET}":"192.168.254.1","{#SEQ}":1,"{#MS}":1.000,"{#OK}":1},
  ...
  {"{#TARGET}":"192.168.254.1","{#TYPE}":"summary","{#SUCCESS_RATIO}":1.0000,"{#AVG_MS}":5.333}
]
```

**Full Mode (-output full):**
Verbose format with metadata (for debugging):
```json
{
  "target": "192.168.254.1",
  "count": 3, "timeout_ms": 1000, "ttl": 64, "len": 32,
  "data": [...],
  "summary": {"success_ratio": 1.0000, "avg_ms": 5.333}
}
```

=== ARCHITECTURE ===

Single C source file with Windows API dependencies:
- winsock2.h - Network address resolution (getaddrinfo)
- iphlpapi.h - ICMP API (IcmpCreateFile, IcmpSendEcho, Icmp6SendEcho2)
- icmpapi.h - ICMP structures and constants

No external libraries or DLLs required beyond Windows system libraries.

Components:
- ping_ipv4() - IPv4 ICMP ping using IcmpSendEcho
- ping_ipv6() - IPv6 ICMP ping using Icmp6SendEcho2
- print_json_data_only() - Default array output
- print_json_lld() - LLD discovery format
- print_json_full() - Verbose format with metadata

=== PARAMETERS ===

**Metric Key:** ping.icmp[target,count,timeout]

Parameters:
- target (required) - Hostname or IP address
- count (optional) - Number of pings (default: 3, max: 100)
- timeout (optional) - Timeout per ping in milliseconds (default: 1000)

Internal parameters (hardcoded in Go wrapper):
- ttl: 64 (IPv4 TTL / IPv6 hop limit)
- len: 32 (payload size in bytes)
- df: 0 (IPv4 Don't Fragment flag)
- ipv6: 0 (prefer IPv4, fallback to IPv6)

Configuration (zabbix_agent2.d/plugins.d/pingtool.conf):
- Plugins.Pingtool.System.Path (required) - Path to pingtool.exe
- Plugins.Pingtool.DebugLevel (optional) - 0-5, default 0
- Plugins.Pingtool.DefaultCount (optional) - Default ping count, default 3
- Plugins.Pingtool.DefaultTimeout (optional) - Default timeout in ms, default 1000

**Zabbix Item Examples:**

1. Success Ratio:
   - Key: `ping.icmp[192.168.254.1,3,1000]`
   - Preprocessing: JSONPath `$[?(@.type=="summary")].success_ratio.first()`
   - Type: Numeric (float)

2. Average Response Time:
   - Key: `ping.icmp[192.168.254.1,3,1000]`
   - Preprocessing: JSONPath `$[?(@.type=="summary")].avg_ms.first()`
   - Type: Numeric (float)

3. Last Ping Time:
   - Key: `ping.icmp[192.168.254.1,3,1000]`
   - Preprocessing: JSONPath `$[-2].ms` (second-to-last, excluding summary)
   - Type: Numeric (float)

4. Packet Loss Percentage:
   - Key: `ping.icmp[192.168.254.1,3,1000]`
   - Preprocessing: JSONPath `$[?(@.type=="summary")].success_ratio.first()`
   - Preprocessing: JavaScript `return (1 - value) * 100;`
   - Type: Numeric (float)

=== TECHNICAL NOTES ===

**Windows ICMP API:**
- IcmpCreateFile() - Creates ICMP handle (IPv4)
- IcmpSendEcho() - Sends ICMP echo request (IPv4)
- Icmp6CreateFile() - Creates ICMPv6 handle
- Icmp6SendEcho2() - Sends ICMPv6 echo request
- No admin privileges required (unlike raw sockets)

**Response Time Measurement:**
- Uses GetTickCount() for manual timing (fallback)
- IcmpSendEcho provides RoundTripTime in reply structure (when available)
- IPv6 lacks RoundTripTime field, always uses manual measurement
- Resolution: 1ms (GetTickCount granularity)

**Error Handling:**
- Timeouts: ms = null, ok = false, err = "timeout"
- Host unreachable: ms = null, ok = false, err = "bad_destination"
- ICMP errors: ms = null, ok = false, err = "icmp_error"
- Success: ms = <float>, ok = true, no err field

**Memory Management:**
- Samples allocated on heap (calloc)
- Reply buffers sized for ICMP_ECHO_REPLY + payload + overhead
- All allocations freed before exit
- No memory leaks

=== KNOWN LIMITATIONS ===

- Single target per invocation (by design for Zabbix integration)
- Outbound ICMP may be blocked by firewall/network
- IPv6 requires Windows Vista/Server 2008 or newer
- Localhost always shows ~0ms (sub-millisecond responses)
- Max 100 pings per invocation (sanity limit)
- 1ms resolution (GetTickCount granularity)
